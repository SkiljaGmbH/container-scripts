Site Management Tool (grant initial rights: license managers, organization admins, organizations)
--------------------------------------------------------------------------------------------------
Needed once after the first install, and again after adding a module. Run it only after all module
pods were Ready once (their first start creates the databases):
  kubectl get pods -n {{ .Release.Namespace }} -l app.kubernetes.io/instance={{ .Release.Name }}

1. Start the CLI pod (PowerShell; in bash use: cat <<'EOF' | kubectl apply -f - ... EOF):

@"
apiVersion: v1
kind: Pod
metadata:
  name: site-management-tool
  namespace: {{ .Release.Namespace }}
spec:
  restartPolicy: Never
  nodeSelector:
    kubernetes.io/arch: amd64
  containers:
    - name: site-management-tool
      image: {{ dig "image" "repository" "skilja/sitemanagement" $smt }}:{{ dig "image" "tag" "8.0" $smt }}
      stdin: true
      tty: true
      env:
        - name: TERM
          value: xterm-256color
      envFrom:
        - secretRef:
            name: {{ $smtName }}-secrets
{{- if $dbSecret }}
        - secretRef:
            name: {{ $dbSecret }}
{{- end }}
"@ | kubectl apply -f -

2. Connect (Windows Terminal or WSL, the menu needs a modern terminal):
     kubectl attach -it site-management-tool -n {{ .Release.Namespace }}
   Output from before the attach is only visible in: kubectl logs site-management-tool -n {{ .Release.Namespace }}

3. Select the service by number and assign the rights (quickest: add your own admin user as
   organization admin). Then restart the module pods to pick up the new rights:
     kubectl rollout restart deployment -n {{ .Release.Namespace }} -l app.kubernetes.io/instance={{ .Release.Name }}

4. Delete the pod (it does not restart on its own):
     kubectl delete pod site-management-tool -n {{ .Release.Namespace }}

Show these notes again: helm get notes {{ .Release.Name }} -n {{ .Release.Namespace }}
{{- end }}
